# 01. Архитектура

Статус: черновик. Стек принят в `D-08` (`../Service/decisions.md`); части бэкенда и данных подтверждают Прощаев Алексей и Кубанов Сергей.

## Путь запроса

```
Интерфейс → API → проверка длины и счётчик → перевод/предобработка запроса → поиск по индексу BM25 → топ-k документов → промпт → LLM → ответ в интерфейс
```

Шаг перевода запроса в английские ключевые слова работает по решению `D-22`: корпус на английском, запрос на русском. Он добавляет к цепочке второй вызов LLM и вторую точку отказа, поэтому ошибка перевода обрабатывается как ошибка поиска (`RULE-ERR-01`).

## Стек

| Слой             | Выбор                                                                    |
| ---------------- | ------------------------------------------------------------------------ |
| Интерфейс        | React 18, Vite, TypeScript, `react-router-dom`, обычный CSS, шрифт Inter |
| API              | Python 3.12 и новее, FastAPI, Pydantic                                   |
| Вход и сессия    | подписанная cookie (`HttpOnly`, `SameSite=Lax`), данные из `.env`        |
| Поиск            | собственный BM25 на Python, индекс в памяти и в файле                    |
| Корпус           | JSONL в `code/data`, снимок Modrinth API v2                              |
| Счётчик запросов | SQLite из стандартной библиотеки                                         |
| LLM              | GigaChat, библиотека `gigachat` за обёрткой `llm.py`, ключ в `.env` (`D-18`) |
| Проверки         | pytest, pandas (benchmark), Vitest (интерфейс)                           |
| Зависимости      | `uv` для Python, `npm` для интерфейса                                    |

В рабочем виде бэкенд раздаёт собранный интерфейс как статику: один процесс и один порт. При разработке интерфейс запускается отдельно (Vite) и обращается к API через прокси (`02-running.md`).

## Компоненты

| Компонент                                   | Назначение                                                     | Ответственный   |
| ------------------------------------------- | -------------------------------------------------------------- | --------------- |
| Интерфейс (`code/frontend`)                 | Три экрана, боковая панель, талисман, вызовы API               | Верзаков Никита |
| Интеграция (`code/backend`)                 | API, сессии и роли, счётчик запросов, связь поиска и LLM       | Прощаев Алексей |
| Поиск (`code/backend` или отдельный модуль) | Предобработка, индекс BM25, ранжирование                       | Кубанов Сергей  |
| Корпус (`code/data`)                        | Снимок описаний модов                                          | Кубанов Сергей  |
| Заглушка API (`code/frontend/dev-stub`)     | Ответы API на время разработки интерфейса без бэкенда (D-26) | Верзаков Никита |

## Устройство бэкенда

```
code/backend/
├── main.py          приложение FastAPI (create_app), методы API, проверка роли
├── auth.py          проверка логина и пароля, подписанная cookie (HMAC-SHA256)
├── stats.py         счётчики аналитики в SQLite
├── config.py        чтение .env из корня репозитория
├── llm.py           обёртка над LLM: протокол LLM, GigaChatLLM, LLMError
├── translate.py     перевод запроса в английские ключевые слова
├── explain.py       объяснение по найденным модам или отказ
├── pyproject.toml   зависимости для uv; requirements.txt — для pip
```

Сессия: cookie `session` = `роль:случайное значение.подпись`; сервер ничего не хранит, «Выйти» удаляет cookie. `/api/search` ищет по корпусу через `ModSearch` (`D-17`): индекс загружается один раз при старте приложения. Запрос с кириллицей до поиска переводится в английские ключевые слова через GigaChat (`translate.py`, `D-18`). Если выдача не пустая, GigaChat пишет объяснение по найденным модам или отказ (`explain.py`, `D-19`); при ошибке LLM `answer` равен `null`.

## Устройство интерфейса

```
code/frontend/src/
├── main.tsx, App.tsx      вход в приложение, маршруты и защита по роли
├── api.ts                 вызовы API и типы ответов
├── library/               чистые функции: проверка запроса, форматирование, тема
├── mascot/                костюмы и логика выбора костюма, компонент «Зомби», скелет
├── components/            логотип, значки, карточка мода, боковая панель, форма запроса, переключатель темы
├── pages/                 LoginPage, SearchPage, AdminPage
└── styles/                tokens.css (цвета, размеры) и app.css
```

Список чатов и сообщений хранится в `localStorage` браузера (`D-10`), выбранный чат и черновик — в памяти компонента `SearchPage`. На сервер история не отправляется (`RULE-UI-07`, `RULE-UI-11`). Удаление чата тоже локальное: запись убирается из состояния и `localStorage` после подтверждения (`RULE-UI-13`). Тема интерфейса хранится в `localStorage` (`RULE-UI-12`).

Счётчики аналитики для админ-панели ведёт API. В заглушке API они сохраняются в `code/frontend/.dev-stub/analytics.json` (каталог исключён из Git) и не сбрасываются при перезапуске; постоянное хранилище реального бэкенда — `GAP-16` (`D-15`). Админ-панель обновляет показатели автоматически (`RULE-ADM-07`). Контракт ответа — `04-api-and-access.md`.

Защита маршрутов: при каждом переходе интерфейс запрашивает `GET /api/auth/me` и переадресует по таблице из `../Product/04-interface-and-behavior.md` (раздел 9). Скрытие экранов в интерфейсе не заменяет проверку на сервере: каждый защищённый метод API сам проверяет роль (`RULE-AUTH-05`).

## Границы

Интеграция и поиск работают в одном процессе (`D-17`): бэкенд импортирует пакет `code/search` и вызывает `ModSearch.open()` при старте и `search(query, k)` на каждый запрос. Поиск отвечает за предобработку, индекс и ранжирование; бэкенд — за проверку запроса, перевод (`D-22`), формат ответа API, счётчики и вызов LLM.
