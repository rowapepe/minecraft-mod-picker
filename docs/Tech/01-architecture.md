# 01. Архитектура

Статус: черновик. Стек принят в `D-08` (`../Service/decisions.md`); части бэкенда и данных подтверждают Прощаев Алексей и Кубанов Сергей.

## Путь запроса

```
Интерфейс → API → проверка длины и счётчик → перевод/предобработка запроса → поиск по индексу BM25 → топ-k документов → промпт → LLM → ответ в интерфейс
```

Шаг перевода запроса в английские ключевые слова работает при решении GAP-01: корпус на английском, запрос на русском. Он добавляет к цепочке второй вызов LLM и вторую точку отказа, поэтому ошибка перевода обрабатывается как ошибка поиска (`RULE-ERR-01`).

## Стек

| Слой             | Выбор                                                                    |
| ---------------- | ------------------------------------------------------------------------ |
| Интерфейс        | React 18, Vite, TypeScript, `react-router-dom`, обычный CSS, шрифт Inter |
| API              | Python 3.12 и новее, FastAPI, Pydantic                                   |
| Вход и сессия    | подписанная cookie (`HttpOnly`, `SameSite=Lax`), данные из `.env`        |
| Поиск            | собственный BM25 на Python, индекс в памяти и в файле                    |
| Корпус           | JSONL в `code/data`, снимок Modrinth API v2                              |
| Счётчик запросов | SQLite из стандартной библиотеки                                         |
| LLM              | SDK выбранного провайдера за тонкой обёрткой, ключ в `.env`              |
| Проверки         | pytest, pandas (benchmark), Vitest (интерфейс)                           |
| Зависимости      | `uv` для Python, `npm` для интерфейса                                    |

В рабочем виде бэкенд раздаёт собранный интерфейс как статику: один процесс и один порт. При разработке интерфейс запускается отдельно (Vite) и обращается к API через прокси (`02-running.md`).

## Компоненты

| Компонент                                   | Назначение                                                     | Ответственный   |
| ------------------------------------------- | -------------------------------------------------------------- | --------------- |
| Интерфейс (`code/frontend`)                 | Три экрана, боковая панель, талисман, вызовы API               | Верзаков Никита |
| Интеграция (`code/backend`)                 | API, сессии и роли, счётчик запросов, связь поиска и LLM       | Прощаев Алексей |
| Поиск (`code/backend` или отдельный модуль) | Предобработка, индекс BM25, ранжирование                       | Кубанов Сергей  |
| Корпус (`code/data`)                        | Снимок описаний модов                                          | Кубанов Сергей  |
| Заглушка API (`code/frontend/dev-stub`)     | Ответы API на время разработки интерфейса без бэкенда (GAP-13) | Верзаков Никита |

## Устройство интерфейса

```
code/frontend/src/
├── main.tsx, App.tsx      вход в приложение, маршруты и защита по роли
├── api.ts                 вызовы API и типы ответов
├── lib/                   чистые функции: проверка запроса, форматирование числа
├── mascot/                костюмы и логика выбора костюма, компонент «Зомби», скелет
├── components/            логотип, значки, карточка мода, боковая панель, форма запроса
├── pages/                 LoginPage, SearchPage, AdminPage
└── styles/                tokens.css (цвета, размеры) и app.css
```

Состояние экрана поиска (список записей сессии, выбранная запись, черновик) хранится в памяти компонента `SearchPage` и не записывается ни в `localStorage`, ни на сервер (`RULE-UI-07`).

Защита маршрутов: при каждом переходе интерфейс запрашивает `GET /api/auth/me` и переадресует по таблице из `../Product/04-interface-and-behavior.md` (раздел 9). Скрытие экранов в интерфейсе не заменяет проверку на сервере: каждый защищённый метод API сам проверяет роль (`RULE-AUTH-05`).
