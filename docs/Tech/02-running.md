# 02. Запуск и настройки

Статус: интерфейс запускается; бэкенд ищет по корпусу собственным BM25, запрос с кириллицей переводится через GigaChat, GigaChat пишет объяснение по найденным модам (`D-17`…`D-19`).

## Требования

- Node.js 20 и новее, npm — для интерфейса (`code/frontend`).
- Python 3.12 и новее, `uv` (или `pip`) — для бэкенда (`code/backend`).

## Настройки

Все настройки проекта лежат в одном файле `.env` в корне репозитория. Его читают интерфейс (заглушка API и прокси), бэкенд и скрипты. Шаблон — `.env.example` (имена без значений). Файл `.env` в Git не попадает.

| Переменная                      | Для чего                                                                                                       | Кто читает             |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------- |
| `USER_LOGIN`, `USER_PASSWORD`   | Учётная запись пользователя (`RULE-AUTH-02`)                                                                   | бэкенд, заглушка API   |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Учётная запись администратора                                                                                  | бэкенд, заглушка API   |
| `SESSION_SECRET`                | Ключ подписи cookie сессии                                                                                     | бэкенд                 |
| `LLM_API_KEY`, `LLM_MODEL`      | Ключ авторизации GigaChat и модель (по умолчанию `GigaChat`) (`D-18`)                                          | бэкенд                 |
| `LLM_SCOPE`                     | Версия API GigaChat; для физлиц `GIGACHAT_API_PERS` (по умолчанию)                                              | бэкенд                 |
| `LLM_CA_BUNDLE`                 | Путь к сертификатам Минцифры (`.pem`); по умолчанию `certs/russian_trusted_ca.pem` из репозитория               | бэкенд                 |
| `LLM_BASE_URL`                  | Адрес GigaChat API; по умолчанию `https://gigachat.devices.sberbank.ru/api/v1`                                 | бэкенд                 |
| `MODRINTH_USER_AGENT`           | `User-Agent` при выгрузке корпуса                                                                              | скрипты выгрузки       |
| `API_TARGET`                    | Адрес бэкенда для прокси Vite, например `http://localhost:8000`; если не задан, работает заглушка API (D-26) | интерфейс (разработка) |

### Вход при локальном запуске

Чтобы войти при локальной разработке, впишите в `.env` такие значения:

| Роль          | Переменные                                  | Логин и пароль      | Что откроется |
| ------------- | ------------------------------------------- | ------------------- | ------------- |
| Пользователь  | `USER_LOGIN=player`, `USER_PASSWORD=player` | `player` / `player` | экран поиска  |
| Администратор | `ADMIN_LOGIN=admin`, `ADMIN_PASSWORD=admin` | `admin` / `admin`   | админ-панель  |

Эти значения нужны только для локальной разработки и проверки макета. Для любого общего или публичного стенда задавайте другие логины и пароли (D-28).

## Запуск интерфейса

```bash
cp .env.example .env     # в корне репозитория, затем вписать значения из таблицы выше
cd code/frontend
npm install
npm run dev              # http://localhost:5173
```

Без `API_TARGET` `npm run dev` поднимает заглушку API (`code/frontend/dev-stub`): вход, поиск и аналитика работают на заготовленных ответах. Заглушка нужна только для разработки и проверки макета, в сборку она не входит. Счётчики запросов, входов и запросов по дням сохраняются в `code/frontend/.dev-stub/analytics.json`: каталог исключён из Git, значения переживают перезапуск `npm run dev`, но относятся только к локальной разработке (`D-15`). Удалить накопленную статистику можно удалением этого файла.

Особые запросы заглушки для проверки состояний: `!пусто` — «Нет результатов» (увеличивает долю запросов без результатов), `!ошибка` — «Ошибка поиска», `!безответа` — «Результаты без объяснения».

Прочие команды:

```bash
npm run build            # сборка в code/frontend/dist
npm run typecheck        # проверка типов
npm test                 # тесты Vitest
```

## Запуск приложения целиком

### Бэкенд

Команды выполняются из `code/`. Бэкенд читает тот же `.env` в корне репозитория (`USER_*`, `ADMIN_*`, `SESSION_SECRET`). Если `SESSION_SECRET` пуст, берётся случайный ключ и сессии сбрасываются при перезапуске.

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/uvicorn backend.main:app --reload --port 8000   # http://localhost:8000/api/health
```

С `uv`: `uv run --project backend uvicorn backend.main:app --reload --port 8000`.

Чтобы интерфейс работал с бэкендом вместо заглушки, впишите в `.env` `API_TARGET=http://localhost:8000` и перезапустите `npm run dev`. Описание методов в браузере: `http://localhost:8000/api/docs`.

Счётчики аналитики хранятся в SQLite `code/backend/.data/analytics.sqlite3` (каталог исключён из Git); путь меняется переменной `BACKEND_DB_PATH`. Удаление файла сбрасывает статистику.

При старте бэкенд загружает индекс BM25 из `code/data/index.json`; если файла нет или он построен по другому корпусу, индекс строится заново (около секунды) и сохраняется. Запрос с кириллицей перед поиском переводится в английские ключевые слова через GigaChat (`D-18`); без `LLM_API_KEY` перевода нет, и русские запросы обычно дают «ничего не найдено». По найденным модам GigaChat пишет объяснение или отказ (`D-19`); без ключа `answer` равен `null`, и интерфейс показывает «Объяснение сейчас недоступно».

#### Ключ GigaChat

1. Зарегистрируйтесь в [личном кабинете GigaChat API](https://developers.sber.ru/studio) как физлицо и создайте проект GigaChat API.
2. В настройках проекта получите **ключ авторизации** (Authorization key) и впишите его в `.env` как `LLM_API_KEY`. `LLM_SCOPE` для физлиц — `GIGACHAT_API_PERS`.
3. Серверы GigaChat используют сертификаты Минцифры, которых нет в стандартных списках доверенных (macOS, Windows, `certifi`). Они лежат в репозитории: `certs/russian_trusted_ca.pem` — корневой «Russian Trusted Root CA» (до 2032 года) и выпускающий «Russian Trusted Sub CA» (до 06.03.2027), скачаны с [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt). Бэкенд берёт этот файл по умолчанию на любой ОС, устанавливать сертификат в систему не нужно. Проверку сертификатов не отключайте. Когда Sub CA истечёт, файл нужно обновить с того же адреса.
4. Запросы идут на классический адрес `gigachat.devices.sberbank.ru`: новый `api.giga.chat`, который библиотека `gigachat` 0.2 использует по умолчанию, из некоторых сетей не отвечает (`ConnectTimeout` при TLS-рукопожатии, проверено 2026-11-18). Адрес меняется переменной `LLM_BASE_URL`.

Проверка перевода без интерфейса (из `code/`):

```bash
backend/.venv/bin/python -c "from backend.config import Settings; from backend.llm import make_llm; from backend.translate import translate_query; print(translate_query(make_llm(Settings.load()), 'хочу магию с заклинаниями'))"
```

После изменения `.env` бэкенд нужно перезапустить: `--reload` следит только за кодом.
