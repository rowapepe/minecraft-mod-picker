# 05. Тесты и проверки

Статус: для КТ1 описано, для КТ2 заготовка.

## Контрольная точка 1

Проверка макета по сценариям с этапом «макет» из `../Product/02-users-and-scenarios.md`: GWT-02, GWT-03, GWT-04, GWT-14…GWT-21, GWT-23…GWT-31 (требования REQ-02, REQ-03, REQ-16…REQ-21, REQ-23…REQ-28 из `../Product/03-requirements.md`). Результат каждой проверки записывается в `../Service/verification.md`.

Как выполняется:

- ручная проверка в браузере на локальном запуске (`02-running.md`), в том числе на ширине 360–390 px;
- автоматические тесты Vitest для логики без интерфейса: выбор костюма зомби (`RULE-MASCOT-02`), проверка запроса (`RULE-UI-01`, `RULE-UI-02`), форматирование числа запросов; запуск `npm test` в `code/frontend`;
- проверка типов `npm run typecheck` и сборка `npm run build`.

Сценарии GWT-25 и GWT-27 проверяются на ответах заглушки API (GAP-13), поэтому они подтверждают поведение интерфейса, а не качество поиска.

## Контрольная точка 2

- Тесты индекса BM25 на маленьком корпусе с известным ответом.
- Сценарии с этапом «КТ2»: GWT-01, GWT-05…GWT-13, GWT-22 (REQ-01, REQ-04…REQ-07, REQ-09…REQ-13, REQ-21 в части реального счёта, REQ-22).
- Benchmark: тестовый набор запросов, размеченные релевантные документы (не менее трёх на запрос), метрики Recall@k и MRR (REQ-14, REQ-15, `RULE-QA-01…05`).
