# 05. Тесты и проверки

Статус: для КТ1 описано; для КТ2 описаны тесты поиска и benchmark поиска, проверка ответов LLM — впереди.

## Контрольная точка 1

Проверка макета по сценариям с этапом «макет» из `../Product/02-users-and-scenarios.md`: GWT-02, GWT-03, GWT-04, GWT-14…GWT-21, GWT-23…GWT-37 (требования REQ-02, REQ-03, REQ-16…REQ-21, REQ-23…REQ-34 из `../Product/03-requirements.md`). Результат каждой проверки записывается в `../Service/verification.md`.

Как выполняется:

- ручная проверка в браузере на локальном запуске (`02-running.md`), в том числе на ширине 360–390 px;
- автоматические тесты Vitest для логики без интерфейса: выбор костюма зомби (`RULE-MASCOT-02`), проверка запроса (`RULE-UI-01`, `RULE-UI-02`), форматирование числа запросов и доли (`RULE-ADM-06`); запуск `npm test` в `code/frontend`;
- проверка типов `npm run typecheck` и сборка `npm run build`.

Сценарии GWT-25, GWT-27, GWT-32 и GWT-33 проверяются на ответах заглушки API (GAP-13), поэтому они подтверждают поведение интерфейса и счётчиков, а не качество поиска. GWT-35 не зависит от API: удаление затрагивает только локальную историю браузера. GWT-36 и GWT-37 проверяются на заглушке: аналитика сохраняется в `.dev-stub/analytics.json` и обновляется автоматически; для реального бэкенда постоянное хранилище остаётся в `GAP-16`.

## Контрольная точка 2

- Тесты индекса BM25 на маленьком корпусе с известным ответом: `code/tests/test_bm25.py` повторяет пример презентации «Занятие 3» (`IDF ≈ 0,470`, баллы A = 0,940, B = C = 0,470, при `k = 2` — A и B), пример индекса из методички (раздел 1.4), насыщение частоты (слайд 14), поправку на длину (слайд 15), порядок при равных баллах, пустую выдачу и загрузку индекса из файла. Запуск из `code/`: `python -m pytest tests`.
- Сценарии с этапом «КТ2»: GWT-01, GWT-05…GWT-13, GWT-22 (REQ-01, REQ-04…REQ-07, REQ-09…REQ-13, REQ-21 в части реального счёта, REQ-22).
- Benchmark (`GAP-18`, `REQ-14`, `REQ-15`, `RULE-QA-01…05`) — `code/benchmark`:
  - `corpus.jsonl` — 30 документов `D01…D30`, копия из снимка `code/data/mods.jsonl` (`make_corpus.py`, список модов и тем в нём); поле `id` — id Modrinth (`RULE-QA-04`);
  - `questions.json` — 10 обычных вопросов (русская формулировка, английский запрос, релевантные `D…`, эталон) и 5 ловушек; `k = 5`;
  - `python -m benchmark.run` (из `code/`) считает Recall@5 и MRR@5 по 10 обычным вопросам для базовой настройки и вариантов «одна настройка за раз» (`k1`, `b`, лемматизация, стоп-слова), а также на полном снимке; Accuracy и Correct Rejection Rate — по `answers.jsonl` с оценками ответов LLM, если он есть;
  - результаты: `results/report.md`, `results/search-results.json` (выдача по всем 15 вопросам с вкладами слов); сводка и вывод переносятся в `../Service/verification.md`;
  - тесты: `code/tests/test_benchmark.py` — метрики на примерах слайдов 33–34 и состав набора.
