# Minecraft Mod Picker — роли и сценарии

## 1. Назначение документа

Документ описывает, кто пользуется приложением, и содержит сценарии поведения в формате Given/When/Then. Это основной файл для ручной проверки макета, приёмки, тестов и работы кодингового агента.

Каждый сценарий имеет идентификатор `GWT-NN`. Идентификаторы не переиспользуются: если сценарий устарел, он помечается как отменённый.

## 2. Роли

В системе две роли. Каждой соответствует одна фиксированная учётная запись. Регистрации нет, других учётных записей создать нельзя (`RULE-AUTH-01`).

| Роль                 | Учётная запись      | Что видит после входа |
| -------------------- | ------------------- | --------------------- |
| Пользователь (игрок) | одна, фиксированная | экран поиска          |
| Администратор        | одна, фиксированная | админ-панель          |

Без входа доступен только экран входа.

### 2.1. Пользователь (игрок)

Пользователь — игрок, которому нужно подобрать моды. Он входит под учётной записью пользователя.

Пользователь должен иметь возможность:

- войти по логину и паролю;
- выйти из системы;
- ввести описание задачи текстом;
- выбрать готовый пример запроса;
- запустить поиск;
- видеть, что поиск выполняется;
- просмотреть список найденных модов;
- прочитать ответ с объяснением;
- открыть страницу мода на Modrinth;
- повторить поиск с другой формулировкой;
- сворачивать и разворачивать боковую панель;
- видеть список своих запросов в этой сессии и возвращаться к ответу на любой из них;
- начать новый поиск, не теряя список запросов.

Пользователь не видит админ-панель.

### 2.2. Администратор

Администратор следит за использованием приложения. Он входит под учётной записью администратора.

Администратор должен иметь возможность:

- войти по логину и паролю;
- выйти из системы;
- увидеть в админ-панели числовую аналитику; сейчас это число поисковых запросов, выполненных пользователем (состав показателей может расширяться, GAP-12).

Администратор не ищет моды, не видит тексты запросов и не управляет учётными записями (GAP-11).

## 4. Сценарии

Сценарии `GWT-01`…`GWT-13` и `GWT-24`…`GWT-29`, `GWT-31` выполняются на экране поиска после входа под учётной записью пользователя. Сценарии входа, доступа и админ-панели — `GWT-14`…`GWT-23` и `GWT-30`.

### GWT-01. Успешный поиск по задаче

**Given** экран поиска открыт, в поле ввода нет текста.
**When** игрок вводит «хочу автоматизировать ферму» и нажимает «Найти моды».
**Then** кнопка поиска становится недоступной и показывается индикатор загрузки; после завершения показываются блок ответа и от одной до `k` карточек модов; у каждой карточки есть название, короткое описание и ссылка «Открыть на Modrinth».

### GWT-02. Пустой запрос

**Given** поле ввода пустое.
**When** игрок нажимает «Найти моды».
**Then** запрос не отправляется, под полем появляется сообщение «Опишите задачу, чтобы начать поиск», область результатов не меняется.

### GWT-03. Запрос из одних пробелов

**Given** в поле ввода только пробелы и переводы строк.
**When** игрок нажимает «Найти моды».
**Then** поведение совпадает с `GWT-02`.

### GWT-04. Слишком длинный запрос

**Given** игрок вводит или вставляет текст длиннее допустимого.
**When** длина текста достигает предела.
**Then** поле не принимает лишние символы, счётчик показывает предельное значение, поиск остаётся доступным для уже введённого текста.

### GWT-05. Выбор примера запроса

**Given** экран поиска открыт, показаны примеры запросов.
**When** игрок нажимает на один из примеров.
**Then** текст примера подставляется в поле ввода и поиск запускается сразу, как в `GWT-01`.

### GWT-06. Ничего не найдено

**Given** запрос корректный, но ни один документ не получил положительной оценки.
**When** поиск завершается.
**Then** показывается сообщение «Подходящих модов не найдено. Попробуйте описать задачу другими словами»; блок ответа и карточки не показываются; форма остаётся доступной.

### GWT-07. Переход на страницу мода

**Given** на экране показаны карточки модов.
**When** игрок нажимает «Открыть на Modrinth» в одной из карточек.
**Then** страница этого мода открывается в новой вкладке, приложение остаётся открытым с прежними результатами.

### GWT-08. Повторный поиск

**Given** на экране показаны результаты предыдущего запроса.
**When** игрок меняет текст и снова нажимает «Найти моды».
**Then** предыдущие результаты заменяются: после загрузки показаны только результаты нового запроса.

### GWT-09. Ошибка LLM при успешном поиске

**Given** поиск по индексу выполнен и вернул документы, но сервис LLM недоступен.
**When** система пытается получить ответ с объяснением.
**Then** карточки модов показываются, а вместо ответа выводится сообщение «Объяснение сейчас недоступно, но вот найденные моды».

### GWT-10. Ошибка поиска

**Given** запрос корректный, но поиск завершился внутренней ошибкой.
**When** система обрабатывает запрос.
**Then** показывается сообщение «Не удалось выполнить поиск. Попробуйте ещё раз»; технические детали ошибки игроку не показываются; форма остаётся доступной для повторной попытки.

### GWT-11. Ответ опирается только на найденные моды

**Given** поиск вернул набор документов.
**When** LLM формирует ответ с объяснением.
**Then** в ответе упоминаются только моды из этого набора; моды, которых нет в выдаче, не называются и не рекомендуются.

### GWT-12. Запрос на русском языке

**Given** корпус и индекс на английском, игрок вводит запрос на русском (при условии решения GAP-01).
**When** система обрабатывает запрос.
**Then** запрос приводится к английским ключевым словам, поиск идёт по ним, ответ с объяснением формируется на русском.

### GWT-13. Порядок и состав выдачи

**Given** индекс построен, задан запрос.
**When** система выбирает документы для выдачи.
**Then** документы упорядочены по убыванию оценки BM25; в выдачу попадают не более `k` документов; документы с нулевой оценкой в выдачу не попадают.

### GWT-14. Вход пользователя

**Given** открыт экран входа, вход не выполнен.
**When** человек вводит логин и пароль учётной записи пользователя и нажимает «Войти».
**Then** открывается экран поиска в начальном состоянии; админ-панель недоступна.

### GWT-15. Вход администратора

**Given** открыт экран входа, вход не выполнен.
**When** человек вводит логин и пароль учётной записи администратора и нажимает «Войти».
**Then** открывается админ-панель; экран поиска недоступен.

### GWT-16. Неверный логин или пароль

**Given** открыт экран входа.
**When** человек вводит логин или пароль, не совпадающие ни с одной учётной записью, и нажимает «Войти».
**Then** остаётся экран входа; показывается сообщение «Неверный логин или пароль»; не сказано, что именно неверно; поле пароля очищено; новая попытка возможна сразу.

### GWT-17. Пустые поля на экране входа

**Given** открыт экран входа, логин или пароль не заполнены.
**When** человек нажимает «Войти».
**Then** данные не проверяются, под формой появляется сообщение «Введите логин и пароль».

### GWT-18. Доступ к экранам без входа

**Given** вход не выполнен.
**When** человек пытается открыть экран поиска или админ-панель напрямую (по адресу).
**Then** показывается экран входа; содержимое защищённого экрана не показывается.

### GWT-19. Доступ к чужому экрану

**Given** выполнен вход под одной из учётных записей.
**When** человек пытается открыть экран другой роли напрямую (по адресу): пользователь — админ-панель, администратор — экран поиска.
**Then** показывается экран его собственной роли (пользователю — поиск, администратору — админ-панель); содержимое чужого экрана не показывается.

### GWT-20. Выход из системы

**Given** выполнен вход, открыт экран поиска или админ-панель.
**When** человек нажимает «Выйти».
**Then** открывается экран входа; при возврате назад в браузере или открытии адреса защищённого экрана показывается экран входа (как в `GWT-18`).

### GWT-21. Админ-панель показывает числовую аналитику

**Given** администратор вошёл в систему.
**When** открывается админ-панель.
**Then** на экране видны числовые показатели; сейчас это один показатель — число поисковых запросов пользователя; если запросов ещё не было, показывается 0.

### GWT-22. Счётчик растёт после поиска

**Given** администратор открыл админ-панель и запомнил значение показателя «число запросов» `N`; пользователь ещё не искал.
**When** пользователь выполняет корректный запрос на экране поиска, затем администратор обновляет админ-панель.
**Then** администратор видит `N + 1`; пустой запрос или запрос, не прошедший проверку длины, число не меняет (`RULE-ADM-02`, `RULE-ADM-03`).

### GWT-23. Регистрации нет

**Given** открыт экран входа.
**When** человек осматривает экран.
**Then** на нём нет ссылок и кнопок регистрации, создания учётной записи и восстановления пароля; создать третью учётную запись через интерфейс нельзя.

### GWT-24. Сворачивание боковой панели

**Given** открыт экран поиска, боковая панель раскрыта.
**When** человек нажимает «Свернуть панель».
**Then** панель становится узкой полосой со значками «Развернуть панель», «Новый поиск» и «Выйти» без подписей; основная область занимает освободившееся место; по нажатию «Развернуть панель» панель раскрывается снова.

### GWT-25. Список запросов сессии

**Given** экран поиска открыт.
**When** игрок отправляет два разных запроса подряд, затем нажимает на запись первого запроса в боковой панели.
**Then** в списке две записи, новая сверху; открытая запись выделена; после нажатия на первую запись в ленте показывается ответ на первый запрос, а зомби надет костюм по его тексту; повторный поиск не запускается и число запросов для администратора не меняется.

### GWT-26. Пустой список: «Нет чатов»

**Given** игрок только что вошёл и ещё не отправлял запросов.
**When** раскрыта боковая панель.
**Then** в середине списка показан неподвижный скелет, лежащий на земле, и подпись «Нет чатов»; после первого запроса скелет и подпись исчезают, появляется запись.

### GWT-27. Костюм зомби по тексту запроса

**Given** экран поиска открыт, зомби без костюма, над ним реплика «Привет! Опиши задачу, а я подберу моды.».
**When** игрок отправляет запрос «хочу красивые шейдеры».
**Then** над репликой написано имя «Зомби»; на зомби появляется костюм любителя шейдеров, а пока идёт поиск реплика «Ищу подходящие моды…»; после ответа реплика «Ого, как красиво!». Для запросов про ферму, производительность, магию, бои, шахты и строительство надеваются костюмы фермера, оптимизатора, мага, рыцаря, шахтёра и строителя (`05`, раздел 2.10); для запроса без совпадений зомби без костюма.

### GWT-28. Новый поиск

**Given** открыт запрос с ответом, в списке есть записи.
**When** игрок нажимает «Новый поиск».
**Then** в ленте снова приветствие и четыре примера, поле пустое, зомби без костюма; записи в списке остаются.

### GWT-29. Отправка клавишами

**Given** в поле введён корректный запрос.
**When** игрок нажимает Enter.
**Then** запрос отправляется. При Shift+Enter в поле добавляется перевод строки и запрос не отправляется. Во время поиска нажатие Enter новый запрос не отправляет.

### GWT-30. Админ-панель: загрузка и ошибка

**Given** администратор открывает админ-панель.
**When** данные ещё загружаются, затем при другой попытке сервер недоступен.
**Then** при загрузке вместо числа показана серая плашка и строка «Загружаем данные…»; при ошибке — красное сообщение «Не удалось получить данные. Попробуйте обновить страницу» и нет числа.

### GWT-31. Узкий экран

**Given** окно браузера шириной 360–390 px.
**When** человек открывает экран входа, экран поиска и админ-панель.
**Then** на каждом экране нет горизонтальной прокрутки; на экране входа части идут друг под другом, иллюстрация скрыта; на экране поиска боковая панель скрыта и открывается кнопкой в заголовке поверх страницы; карточка мода переносит ссылку под текст.
