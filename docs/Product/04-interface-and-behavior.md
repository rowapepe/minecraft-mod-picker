# Minecraft Mod Picker — интерфейс и поведение

## 1. Назначение документа

Документ описывает экраны приложения, их внешний вид и связанные с ними состояния.

Этот файл отвечает на вопросы:

- какие экраны есть и как человек между ними попадает;
- какие блоки есть на экране;
- какие данные и действия доступны в каждом блоке;
- какие состояния экрана должен учитывать интерфейс;
- какие проверки выполняются до отправки запроса;
- как устроено оформление и талисман интерфейса.

Сценарии поведения описаны в `02-users-and-scenarios.md`, точные правила — в `05-rules-and-data-meaning.md`. Исходный дизайн (макет в виде холста из трёх экранов) перенесён в `code/frontend`; решения по дизайну — `D-09` в `../Service/decisions.md`.

## 2. Общая структура

Интерфейс состоит из трёх экранов в браузере. Вход в систему обязателен. Свободной навигации между экранами нет: какой экран открыть, определяет роль учётной записи (раздел 9).

| Экран        | Адрес     | Кому доступен      | Описание    |
| ------------ | --------- | ------------------ | ----------- |
| Вход         | `/login`  | всем, кто не вошёл | раздел 7    |
| Админ-панель | `/admin`  | администратору     | раздел 8    |
| Экран поиска | `/search` | пользователю       | разделы 3–6 |

Экран поиска устроен как чат нейросети: слева раздвижная боковая панель, внизу поле ввода, выше него ответ. Блоки экрана поиска:

1. Боковая панель: название приложения, кнопка сворачивания, кнопка «Новый поиск», список запросов сессии, блок пользователя с кнопкой «Выйти».
2. Заголовок основной области: название открытого запроса и подпись об источнике.
3. Лента: пустое состояние с примерами запросов либо выбранный запрос с ответом и карточками модов.
4. Нижняя часть: талисман-зомби над полем ввода справа и форма запроса (поле, счётчик символов, кнопка поиска).

## 3. Экран поиска

Доступен только пользователю после входа (`RULE-AUTH-05`).

### 3.1. Боковая панель

Панель имеет два вида (`RULE-UI-06`, `GWT-24`):

- раскрытая (280 px): логотип и название «Mod Picker», кнопка «Свернуть панель», кнопка «Новый поиск», список «Запросы в этой сессии», блок пользователя («Пользователь», подпись «Поиск модов») и кнопка «Выйти» (`GWT-20`);
- свёрнутая (узкая полоса 64 px): только кнопки «Развернуть панель», «Новый поиск» и «Выйти» в виде значков, без подписей.

На узком экране (до 760 px) панель по умолчанию скрыта полностью; кнопка в заголовке основной области открывает её поверх страницы, фон затемняется, нажатие на затемнение сворачивает панель.

Список «Запросы в этой сессии» (`RULE-UI-07`, `GWT-25`):

- каждый отправленный запрос добавляется в начало списка; запись показывает текст запроса, длинный текст обрезается до 36 символов с многоточием;
- открытый запрос выделен цветом акцента;
- нажатие на запись показывает в основной области ответ на этот запрос (повторный поиск не выполняется и счётчик не меняется);
- когда запросов ещё нет, в середине списка лежит поверженный скелет без анимации и подпись «Нет чатов» (`RULE-UI-09`, `GWT-26`).

Список хранится только в памяти открытой вкладки: после обновления страницы или выхода он пуст. Администратор его не видит.

Кнопка «Новый поиск» возвращает основную область в пустое состояние, поле очищается, список остаётся (`RULE-UI-08`, `GWT-28`).

### 3.2. Заголовок основной области

Слева название открытого запроса (для пустого состояния — «Новый поиск»), справа подпись «Поиск по описаниям модов Modrinth» (на узком экране скрыта).

### 3.3. Пустое состояние и примеры запросов

Пока нет открытого запроса, в ленте показываются:

- заголовок «Что хотите сделать в игре?» и пояснение «Опишите задачу, и мы подберём подходящие моды.»;
- четыре карточки-примера:
  - «Хочу автоматизировать ферму и не получить лагов»
  - «Нужен мод, чтобы удобно хранить много предметов»
  - «Хочу улучшить производительность на слабом компьютере»
  - «Ищу мод с новой генерацией мира и приключениями»

Нажатие на карточку отправляет этот текст как запрос сразу (`GWT-05`, `RULE-UI-05`).

### 3.4. Открытый запрос: ответ и карточки

Для открытого запроса лента показывает сверху вниз:

- сообщение пользователя (справа, в рамке цвета акцента);
- ответ системы (слева, с аватаркой): во время поиска — строка «Ищем подходящие моды…» с мигающими квадратами; по завершении — текст ответа с объяснением, подпись «Найденные моды», карточки модов и сноска «Объяснение составлено только по описаниям найденных модов.».

В основной области показывается один запрос: новый поиск и выбор записи в списке заменяют предыдущий вид (`RULE-UI-05`).

### 3.5. Карточка мода

Карточка содержит:

- квадратную плашку с первой буквой названия;
- название мода;
- короткое описание;
- категории (до пяти меток);
- ссылку «Открыть на Modrinth».

Оценка BM25 пользователю не показывается. Ссылка открывает страницу мода в новой вкладке (`GWT-07`, `RULE-UI-04`).

### 3.6. Форма запроса

Форма стоит внизу основной области и состоит из закруглённого блока:

- многострочное поле, которое растёт по мере ввода (до 168 px, дальше прокрутка), с подсказкой-примером «Например: хочу автоматизировать ферму и не получить лагов»;
- слева внизу счётчик символов вида «0 / 500» (`RULE-UI-02`) и, при необходимости, сообщение о валидации красным цветом;
- справа внизу круглая кнопка со стрелкой «Найти моды» (подпись для скринридера и всплывающая подсказка).

Под блоком строка-подсказка «Enter — найти · Shift+Enter — новая строка».

Отправка (`RULE-UI-10`, `GWT-29`):

- кнопка «Найти моды», клавиша Enter, Ctrl+Enter и Cmd+Enter запускают поиск;
- Shift+Enter переносит строку;
- во время поиска кнопка недоступна, повторная отправка не выполняется.

### 3.7. Талисман «Зомби»

Над формой запроса справа стоит маленький зомби в пикселях. Его правила — в `RULE-MASCOT-01…06`, таблица костюмов — в `05-rules-and-data-meaning.md` (раздел 2.10). Коротко:

- у него постоянное имя «Зомби», оно написано над репликой;
- рядом с ним реплика в рамке («облачко»);
- костюм определяется по тексту запроса: шахтёр, маг, любитель шейдеров, рыцарь, строитель, фермер, оптимизатор; без совпадений зомби без костюма;
- при смене костюма новый предмет «падает» на зомби (ступенчатая анимация);
- пока идёт поиск, зомби качается быстрее, а реплика — «Ищу подходящие моды…»;
- на экране входа зомби без костюма сидит на верхней грани карточки входа;
- талисман декоративный (скрыт от скринридера), на поиск и счётчик не влияет.

## 4. Состояния экрана поиска

| Состояние                 | Что видит игрок                                                                                                             |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Начальное                 | Боковая панель со скелетом и «Нет чатов», приветствие и четыре примера, пустая форма, зомби без костюма                     |
| Ошибка ввода              | Сообщение «Опишите задачу, чтобы начать поиск» в строке под полем, лента не меняется                                        |
| Загрузка                  | Сообщение пользователя и строка «Ищем подходящие моды…», кнопка поиска недоступна, зомби в костюме запроса качается быстрее |
| Результаты                | Сообщение пользователя, ответ, карточки модов                                                                               |
| Результаты без объяснения | Вместо ответа сообщение «Объяснение сейчас недоступно, но вот найденные моды», затем карточки модов                         |
| Нет результатов           | Вместо ответа и карточек сообщение «Подходящих модов не найдено. Попробуйте описать задачу другими словами»                 |
| Ошибка поиска             | Вместо ответа сообщение «Не удалось выполнить поиск. Попробуйте ещё раз», карточек нет                                      |
| Свёрнутая панель          | Узкая полоса значков слева, основная область занимает остальную ширину                                                      |

## 5. Действия и переходы на экране поиска

| Действие                                            | Результат                                                                    |
| --------------------------------------------------- | ---------------------------------------------------------------------------- |
| Ввод текста                                         | Обновляется счётчик символов, сообщение об ошибке ввода скрывается           |
| Нажатие «Найти моды» или Enter с корректным текстом | Запись добавляется в список, состояние «Загрузка», затем итоговое состояние  |
| Нажатие «Найти моды» с пустым запросом              | Состояние «Ошибка ввода»                                                     |
| Выбор примера запроса                               | Запрос отправляется сразу                                                    |
| Нажатие на запись в списке                          | В ленте показывается ответ на этот запрос, зомби переодевается по его тексту |
| «Новый поиск»                                       | Пустое состояние, поле очищено, зомби без костюма                            |
| Кнопка сворачивания / разворачивания                | Панель меняет вид                                                            |
| Нажатие «Открыть на Modrinth»                       | Страница мода открывается в новой вкладке                                    |
| «Выйти»                                             | Экран входа (`GWT-20`)                                                       |

## 6. Валидации на экране поиска

| Условие                             | Реакция                                                                |
| ----------------------------------- | ---------------------------------------------------------------------- |
| Поле пустое или состоит из пробелов | Сообщение «Опишите задачу, чтобы начать поиск», запрос не отправляется |
| Длина запроса больше допустимой     | Поле не принимает лишние символы, счётчик показывает предел            |

Остальные проверки (например, доступность сервисов) выполняются вне интерфейса и приводят к состояниям из раздела 4.

## 7. Экран входа

Первый экран приложения. Доступен всем, кто не вошёл.

### 7.1. Блоки

Экран разделён на две части (на узком экране части идут друг под другом):

- левая, с сеткой на фоне: логотип и название «Minecraft Mod Picker», заголовок «Расскажите, что хотите делать в игре. Мы подберём моды.», пояснение «Поиск по описаниям модов с Modrinth и объяснение, почему подошли именно эти моды.» и иллюстрация диалога (на узком экране иллюстрация скрыта);
- правая, с карточкой входа: зомби на верхней грани карточки, заголовок «Вход», пояснение «Войдите, чтобы подобрать моды», поле «Логин», поле «Пароль» (вводимые символы скрыты), строка сообщения об ошибке, кнопка «Войти».

На экране нет ссылок и кнопок регистрации, создания учётной записи и восстановления пароля (`RULE-AUTH-01`, `GWT-23`).

Вход запускается кнопкой «Войти» или клавишей Enter в одном из полей.

### 7.2. Состояния

| Состояние       | Что видит человек                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| Начальное       | Пустая форма, сообщения нет                                                                            |
| Ошибка ввода    | Сообщение «Введите логин и пароль» (красным, со значком), поля с красной рамкой, данные не проверяются |
| Проверка        | Кнопка «Войти» недоступна, надпись «Проверяем…», на кнопке вращающийся значок                          |
| Неверные данные | Сообщение «Неверный логин или пароль», поле пароля очищено, поле логина сохраняет текст                |

### 7.3. Действия

| Действие                             | Результат                              |
| ------------------------------------ | -------------------------------------- |
| Ввод текста в поле                   | Сообщение об ошибке скрывается         |
| «Войти» с пустым логином или паролем | Состояние «Ошибка ввода» (`GWT-17`)    |
| «Войти» с данными пользователя       | Экран поиска (`GWT-14`)                |
| «Войти» с данными администратора     | Админ-панель (`GWT-15`)                |
| «Войти» с неверными данными          | Состояние «Неверные данные» (`GWT-16`) |

## 8. Админ-панель

Доступна только администратору после входа (`RULE-AUTH-05`).

### 8.1. Блоки

Сверху вниз:

1. Верхняя полоса: логотип «Mod Picker», метка «Админ-панель», подпись «Администратор» и кнопка «Выйти» (`GWT-20`).
2. Заголовок «Админ-панель» и пояснение «Числовые показатели использования приложения. Новые значения появляются после обновления страницы.».
3. Числовые показатели (`RULE-ADM-01`): крупная карточка «Поисковых запросов пользователя» с одним числом и подписью «Каждая отправка текста на поиск, независимо от исхода». Рядом карточка «Что считается запросом» с тремя пунктами, повторяющими `RULE-ADM-02`.
4. Блок «Возможные показатели» с меткой «не утверждено»: три неактивные карточки («Запросы по дням», «Число входов», «Доля запросов без результатов»), пунктирные, без чисел. Блок показывает варианты из GAP-12 и убирается или заменяется настоящими показателями после решения по GAP-12.

Набор показателей может расширяться (GAP-12): новые показатели добавляются в блок 3.

### 8.2. Состояния

| Состояние           | Что видит администратор                                                              |
| ------------------- | ------------------------------------------------------------------------------------ |
| Загрузка            | Вместо числа мерцающая серая плашка и строка «Загружаем данные…»                     |
| Показатели показаны | Число запросов, разбитое на группы цифр пробелами; 0, если запросов не было          |
| Ошибка загрузки     | Красная плашка «Не удалось получить данные. Попробуйте обновить страницу», числа нет |

Показатели загружаются при открытии панели. Новые значения администратор получает, обновив страницу (`GWT-22`, `GWT-30`).

## 9. Навигация и доступ

| Ситуация                                        | Что показывается        |
| ----------------------------------------------- | ----------------------- |
| Вход не выполнен, открыт любой адрес приложения | Экран входа (`GWT-18`)  |
| Вход пользователя                               | Экран поиска (`GWT-14`) |
| Вход администратора                             | Админ-панель (`GWT-15`) |
| Пользователь открывает адрес админ-панели       | Экран поиска (`GWT-19`) |
| Администратор открывает адрес экрана поиска     | Админ-панель (`GWT-19`) |
| «Выйти» на любом экране                         | Экран входа (`GWT-20`)  |
| Вход выполнен, открыт адрес экрана входа        | Экран своей роли        |

Правила: `RULE-AUTH-04`, `RULE-AUTH-05`, `RULE-AUTH-06`.

## 10. Оформление

Интерфейс оформлен в тёмной теме по мотивам сайта Modrinth. Значения задаются переменными в `code/frontend/src/styles/tokens.css`.

| Элемент        | Значение                                                                 |
| -------------- | ------------------------------------------------------------------------ |
| Фон страницы   | `#16181c`                                                                |
| Боковая панель | `#1b1d22`                                                                |
| Карточки, поля | `#22252a`, рамка `#2d3036`                                               |
| Основной текст | `#ecf9fb`, второстепенный `#b0bac5`, приглушённый `#8b97a5`              |
| Акцент         | зелёный `#1bd96a` (кнопки, выделение, фокус); текст на акценте `#05210f` |
| Ошибка         | `#ff8f8f`                                                                |
| Шрифт          | Inter, начертания 400–800                                                |
| Скругления     | карточки 18–20 px, поля 12 px, кнопки-пилюли полностью скруглены         |
| Логотип        | зелёный квадрат с тёмными пикселями                                      |

Фокус клавиатуры показывается контуром цвета акцента. Анимации ступенчатые, «пиксельные».

## 11. Адаптивность и доступность

- Интерфейс пригоден для ширины от 360 px без горизонтальной прокрутки страницы (`REQ-28`, `GWT-31`).
- Все интерактивные элементы — настоящие кнопки, ссылки и поля с подписями; у кнопок-значков есть `aria-label`.
- Сообщения об ошибках имеют роль `alert`, индикатор загрузки — роль `status`.
- Если в системе включено «уменьшить движение», анимации отключаются (`RULE-MASCOT-06`).
