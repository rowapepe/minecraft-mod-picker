# Minecraft Mod Picker — требования и проверки

## 1. Назначение документа

Документ перечисляет требования к продукту и для каждого указывает, как его проверить. Требование сформулировано так, чтобы проверка не зависела от субъективной оценки.

Каждое требование имеет идентификатор `REQ-NN`. Идентификаторы не переиспользуются.

Подробное поведение описано в сценариях (`02-users-and-scenarios.md`), точные значения и ограничения — в правилах (`05-rules-and-data-meaning.md`). Результаты проверок записываются в `../Service/verification.md`.

## 2. Как читать таблицу

- «Проверка» — сценарий `GWT-NN`, который нужно выполнить, или иной способ проверки.
- «Этап» — контрольная точка, на которой требование проверяется: `макет` (КТ1, готовый дизайн без реальных и демонстрационных данных) или `КТ2`.

## 3. Требования

### 3.1. Интерфейс и основной сценарий

| ID     | Требование                                                                             | Проверка       | Этап  |
| ------ | -------------------------------------------------------------------------------------- | -------------- | ----- |
| REQ-01 | Игрок может ввести задачу текстом и запустить поиск                                    | GWT-01         | КТ2 |
| REQ-02 | Пустой запрос и запрос из пробелов не запускают поиск; игрок видит подсказку           | GWT-02, GWT-03 | макет |
| REQ-03 | Длина запроса ограничена; игрок видит счётчик символов                                 | GWT-04         | макет |
| REQ-04 | Игрок может выбрать пример запроса одним нажатием                                      | GWT-05         | КТ2 |
| REQ-05 | Результат показан карточками с названием, описанием, категориями и ссылкой на Modrinth | GWT-01, GWT-07 | КТ2 |
| REQ-06 | Если ничего не найдено, игрок видит сообщение с советом переформулировать задачу       | GWT-06         | КТ2 |
| REQ-07 | Повторный поиск заменяет предыдущие результаты                                         | GWT-08         | КТ2 |
