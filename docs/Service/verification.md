# Протокол проверок

## 2026-10-09. Проверка макета (КТ1)

**Что проверялось.** Интерфейс из `code/frontend` по сценариям и требованиям с этапом «макет» (`../Product/02-users-and-scenarios.md`, `../Product/03-requirements.md`).

**Как.**

- `npm run typecheck`, `npm test` (Vitest: 11 тестов, все прошли), `npm run build` (сборка прошла).
- Ручная проверка в браузере на `npm run dev` с заглушкой API (GAP-13): ширина окна 1440 и 360 px, учётные записи — тестовые значения из локального `.env`.

### Замечания по итогам проверки

1. **Блок «Возможные показатели» в админ-панели.** `04` и `RULE-ADM-01` называют единственный показатель, а в дизайне есть три пунктирные карточки-заглушки. Они описаны в `04` (раздел 8.1) как временные до решения `GAP-12`. Если команда решит не показывать неутверждённое, блок убирается одним элементом `<section className="future">` в `AdminPage.tsx`.
2. **Ctrl+Enter.** Прежняя редакция `04` называла для отправки Ctrl/Cmd+Enter; принято Enter (`D-09`), Ctrl+Enter и Cmd+Enter тоже работают.
3. **История запросов.** `RULE-UI-05` («повторный поиск заменяет результаты») сохранён за счёт того, что в ленте виден один запрос; список записей добавлен как `RULE-UI-07`. Если нужна непрерывная лента с накоплением ответов, правило `RULE-UI-05` придётся менять.
4. **Сценарии, которые зависят от заглушки.** GWT-25 и GWT-27 подтверждают поведение интерфейса на заготовленных ответах, а не работу поиска.
